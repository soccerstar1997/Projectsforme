# مستر کباب — وب‌سایت رستوران (Mister Kebab website)

وب‌سایت کامل و فارسی (RTL) برای برند رستوران «مستر کباب»: دوازده بخش روایت‌محور،
از هدر سینمایی با ویدیوی کباب روی زغال تا منوی قابل ویرایش، گالری تصاویر،
فرم واقعی «درخواست رزرو میز» و بخش تماس.

## Stack

| بخش | فناوری |
| --- | --- |
| فرانت‌اند | React 19 + TypeScript + Vite + Tailwind CSS (RTL، فونت Vazirmatn) |
| بک‌اند | Node.js + Express 5 + SQLite (better-sqlite3) |
| اجرا | Docker Compose (`docker-compose.base44.yml`) |

## Running

```bash
docker compose -f docker-compose.base44.yml up -d
# وب‌سایت: http://localhost:3000   |   سلامت API: http://localhost:3000/api/health
```

- سرویس `web` روی پورت ۳۰۰۰ (نقطهٔ ورود عمومی) و سرویس `api` روی پورت داخلی ۸۰۰۰ اجرا می‌شود.
- درخواست‌های `/api/*` از طریق پراکسی خود ویت به API می‌رسند؛ بنابراین کل سایت روی **یک مبدأ**
  سرو می‌شود و نیازی به CORS یا تنظیم کوکی بین‌دامنه‌ای نیست.
- وابستگی‌ها هنگام بالا آمدن کانتینر از `package-lock.json` نصب می‌شوند (والیوم‌های
  `web-node-modules`، `api-node-modules`). پس از تغییر `package.json` یک بار
  `docker compose -f docker-compose.base44.yml up -d --force-recreate web api` کافی است.
- دادهٔ رزروها در والیوم `api-data` (فایل SQLite) نگه داشته می‌شود.

### بررسی‌ها

```bash
docker compose -f docker-compose.base44.yml exec -T web npx tsc --noEmit          # تایپ‌چک
docker compose -f docker-compose.base44.yml exec -T api node -e "fetch('http://127.0.0.1:8000/api/health').then(r=>r.json()).then(console.log)"
```

## 🛠 چه چیزی را مدیر سایت باید ویرایش کند؟

همهٔ مقادیر قابل‌تغییر در پوشهٔ `src/data` جمع شده‌اند و هیچ‌کدام در کامپوننت‌ها سخت‌کد نشده‌اند.

| فایل | چه چیزی را تنظیم می‌کند |
| --- | --- |
| `src/data/site.ts` | نام و شعار برند، لینک‌های ناوبری، **اطلاعات تماس** (تلفن، نشانی، ایمیل، ساعت کاری، نقشه، شبکه‌های اجتماعی)، **لینک سفارش آنلاین**، و تنظیمات فرم رزرو (ساعت‌های پیشنهادی، حداکثر نفرات، بازهٔ روزها) |
| `src/data/menu.ts` | دسته‌بندی‌ها، آیتم‌های منو، توضیحات، قیمت‌ها، وضعیت موجودی، همراه‌های غذا، برچسب‌ها و انتخاب‌های ویژهٔ بخش «پیشنهاد مستر کباب» |
| `src/data/media.ts` | مسیر نه ویدیو، پوسترها، تصاویر غذاهای ویژه و گالری |
| `src/data/reviews.ts` | نظرات واقعی مشتریان (به‌صورت پیش‌فرض خالی است) |
| `src/data/gallery.ts` | تصاویر گالری و متن جانشین آن‌ها |

### اطلاعات تماس

در `src/data/site.ts` مقادیر زیر به‌صورت پیش‌فرض **خالی** هستند:

```ts
export const contact = {
  phone: '',        // مثل '02112345678' یا '09121234567'
  address: '',
  email: '',
  hours: [],        // مثل [{ days: 'هر روز', time: '۱۲:۰۰ تا ۲۳:۳۰' }]
  mapUrl: '',
  socials: [],      // مثل [{ label: 'اینستاگرام', href: 'https://…' }]
};
export const ordering = { url: '', label: 'سفارش آنلاین' };
```

تا وقتی خالی باشند، سایت هیچ نشانی/شماره/ساعت/حساب اجتماعی حدسی نشان نمی‌دهد؛
به‌جایش در بخش «تماس» یک کارت راهنما با فهرست فیلدهای باقی‌مانده دیده می‌شود.
به‌محض پر شدن هر مقدار، همان مورد به‌صورت خودکار در بخش تماس و پاورقی ظاهر می‌شود.
با پر شدن `ordering.url`، دکمهٔ «سفارش آنلاین» در هدر، هدر موبایل، منو و بخش رزرو نمایش داده می‌شود.

### قیمت‌ها و منو

قیمت‌های موجود در `src/data/menu.ts` **دادهٔ نمونه** هستند و قیمت رسمی رستوران محسوب
نمی‌شوند؛ هر آیتم `priceVerified: false` دارد و سایت هم با برچسب «قیمت نمونه» این را به
کاربر می‌گوید. پس از تأیید منو و قیمت‌ها:

1. مقادیر `dishes` را به‌روز کنید و برای آیتم‌های تأییدشده `priceVerified: true` بگذارید،
2. متن `sampleMenuNotice` را خالی/حذف کنید،
3. دسته‌هایی که رستوران ارائه نمی‌دهد را از `menuCategories` بردارید.

### نظرات مشتریان

هیچ نظر، نام، امتیاز یا «بازدید تأییدشده»ای به‌صورت ساختگی وجود ندارد. تا ثبت نظر واقعی،
سایت حالت خالی صادقانه نشان می‌دهد. برای افزودن نظر، آیتم‌های آرایهٔ `reviews` را پر کنید.
امتیاز فقط با `ratingVerified: true` و برچسب بازدید فقط با `verifiedVisit: true` نمایش داده می‌شود.

## 🎬 جایگاه ویدیوها

هر ویدیو یک جایگاه قابل‌جایگزینی است. برای تغییر، فایل هم‌نام را در
`public/media/videos/` عوض کنید یا مسیر را در `src/data/media.ts` تغییر دهید.

| کلید | فایل | بخش |
| --- | --- | --- |
| `hero` | `hero_kebab.mp4` | هدر سینمایی (تمام‌صفحه) |
| `signatureDishes` | `signature_dishes.mp4` | انتخاب‌های ویژهٔ مستر کباب |
| `charcoalGrilling` | `charcoal_grilling.mp4` | هنر کباب، از نزدیک |
| `restaurantInterior` | `restaurant_interior.mp4` | تجربهٔ رستوران |
| `servingFood` | `serving_food.mp4` | لحظهٔ سرو |
| `persianHospitality` | `persian_hospitality.mp4` | مهمان‌نوازی ایرانی |
| `testimonialsBackground` | `testimonials_background.mp4` | پس‌زمینهٔ تجربهٔ مشتریان |
| `reservationCta` | `reservation_cta.mp4` | بخش رزرو و سفارش |
| `footerClosing` | `footer_closing.mp4` | پس‌زمینهٔ بخش تماس و پاورقی |

رفتار ویدیوها: بی‌صدا، `loop`، `playsInline`، بدون کنترل، تزئینی (`aria-hidden`) و با
`object-fit: cover`. هیچ متنی داخل ویدیوها نیست و همهٔ عنوان‌ها و دکمه‌ها عناصر HTML هستند.
ویدیوهای پایین صفحه تا نزدیک‌شدن به ناحیهٔ دید بارگیری نمی‌شوند و بیرون از دید متوقف می‌مانند.
با تنظیم سیستم «کاهش حرکت»، فعال بودن «صرفه‌جویی داده»، اتصال کند یا خطای بارگیری، به‌جای
ویدیو تصویر پوستر نمایش داده می‌شود.

## API

| مسیر | توضیح |
| --- | --- |
| `GET /api/health` | وضعیت سرویس و پایگاه‌داده |
| `POST /api/reservations` | ثبت «درخواست رزرو» با اعتبارسنجی سمت سرور (نام، موبایل ایرانی، تاریخ آینده، ساعت مجاز، تعداد نفرات) |
| `POST /api/reservations/cancel` | لغو درخواست با `trackingCode` + `cancelToken` (رکورد لغوشده از فهرست حذف می‌شود) |

- وضعیت هر درخواست `pending` است؛ **هیچ رزروی خودکار تأیید نمی‌شود** و پیام موفقیت سایت هم
  صریح می‌گوید که تأیید نهایی با تماس رستوران انجام می‌گیرد.
- هیچ مسیری برای فهرست‌کردن درخواست‌ها وجود ندارد (حفاظت از دادهٔ تماس مشتریان).
- محدودیت نرخ ساده (۸ درخواست در ۳۰ دقیقه برای هر IP) و جلوگیری از ثبت تکراری فعال است.
- لاگ‌ها فقط مسیر/وضعیت/زمان را ثبت می‌کنند و هیچ دادهٔ شخصی در لاگ نوشته نمی‌شود.
